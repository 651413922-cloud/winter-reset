## 4. 可利用的控制点（协议级）

经过分析，v2rayN 虽然无原生 API，但存在 4 个可直接操控的入口：

### 控制点 A: SQLite 数据库（主要）
```
guiConfigs/guiNDB.db
├── SubItem        → 订阅管理（增删改订阅URL）
├── ProfileItem    → 节点管理（增删改节点配置）
├── RoutingItem    → 路由规则
├── ProfileExItem  → 延迟/速度数据
└── DNSItem        → DNS 配置
```

### 控制点 B: 运行时配置文件
```
binConfigs/config.json     → 当前运行的 sing-box 配置（包含活动节点）
binConfigs/configTest*.json → 测试用的临时配置
```

### 控制点 C: sing-box 子进程
```
bin/sing_box/sing-box.exe
├── 启动: sing-box run -c config.json
├── 停止: kill process
└── 重启: 停止 → 替换config.json → 启动
```

### 控制点 D: 代理端口检测
```
127.0.0.1:10808 → SOCKS5/HTTP 混合代理
→ 通过 requests 直接验证： requests.get('https://www.google.com', proxies={'https':'socks5://127.0.0.1:10808'})
```

---

## 5. 结论

> **v2rayN = sing-box 的 GUI 外壳**

- GUI 只是数据库管理器 + 配置生成器 + 进程管理器
- **核心引擎是 sing-box**，完全由 config.json 驱动
- 可以用 Python 直接取代 GUI 的 3 个功能：
  1. **读/写 SQLite** → 管理节点和订阅
  2. **生成 config.json** → 切换节点
  3. **控制 sing-box 进程** → 启动/停止/重启

这就实现了**完全的协议级控制**，无需任何 GUI 自动化。
